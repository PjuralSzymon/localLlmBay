# LocalLLMBay contribution node

This folder is the **public source for the software operators install** on their PCs: the official `localllmbay-node` Docker image.

LocalLLMBay is a community queue for local models. Agents (for example OpenCode) talk to the hosted **orchestrator**. Contribution **nodes** pull jobs, run inference on this machine, and send answers back. You earn points when you finish someone else’s job.

## What this repository publishes

**We currently share only the node** — the worker you run with Docker after Setup on the website.

The **website, API, queue, billing, and `/v1` gateway are not in this public tree.** That code stays private for now so we can keep accounts, jobs, and the network safer while the beta is still changing. You do not need those services to review or improve how a node claims a job, talks to Ollama, or runs image/video weights.

This `node/` tree is the **main public repo surface** for operators and contributors who want to inspect what they install.

If you want a change, a clearer log line, a smaller image, better GPU behaviour, or a different model runtime — **open a GitHub issue**. We want that feedback here, not in private chat.

**Issues:** https://github.com/PjuralSzymon/OllamaBay/issues

Say what you run (OS, GPU, VRAM, Docker), what you expected, and what you would like different. Feature ideas are welcome even if you are not sending a patch.

## What a node does

1. Starts **Ollama** inside the container (text / tool hops).
2. Optionally downloads **Hugging Face** weights for image (FLUX.2 Klein 4B) and video (Wan 2.1 T2V 1.3B) and runs them with **PyTorch / Diffusers**. Ollama cannot generate those pictures or clips.
3. Authenticates to the orchestrator with your **node API key**.
4. Heartbeats and **claims** matching jobs (family `graph`, leftover text families, `flux2`, `wan`, `gemma`, …).
5. Decrypts a short-lived job envelope, runs the model, **encrypts** the answer, forgets the prompt.

Tools such as `write` / `bash` / `read` run on the **agent’s PC**, not on this node. The node only runs models.

Official image only. One API key per node. Max **10** nodes per account. Do not put this container on a public inbound port except the local health port you already expose.

## Files in this folder

| File | Role |
|------|------|
| `Dockerfile` | Official image: Ollama **0.33.2**, Python worker, CUDA PyTorch + Diffusers extras. |
| `start.sh` | Boot: GPU scan, `ollama serve`, pull text tags that fit, Hugging Face ensure for Flux/Wan, then `app.py`. |
| `app.py` | HTTP worker: heartbeat, claim, infer (chat / generate / image / video), send answer. |
| `adapt.py` | Local ladders, VRAM/RAM fit, which tags to pull. Keep in sync with the (private) catalog. |
| `hardware.py` | Probe CPU / RAM / NVIDIA / DRM for Setup and heartbeats. |
| `wire_crypto.py` | AES-256-GCM envelopes so prompts are not plaintext on the node hop. |
| `ollama_messages.py` | Map OpenAI-style `messages[]` / `tool_calls` to Ollama `/api/chat`. |
| `ollama_ctx.py` | Context window, `num_predict`, temperature. |
| `ollama_image.py` | Parse Ollama image JSON (legacy). Flux does **not** use Ollama generate. |
| `flux_hf.py` | Diffusers runner for **FLUX.2 Klein 4B** (`black-forest-labs/FLUX.2-klein-4B`). |
| `wan_hf.py` | Diffusers runner for **Wan 2.1 T2V 1.3B**. |
| `tool_parse.py` | Salvage messy model JSON into OpenCode-shaped tool calls. |
| `tool_budget.py` | Trim the Ollama payload so a 16k window still loads. |
| `debug_log.py` | Scrub tokens; optional plaintext dumps (off on the public host). |
| `requirements.txt` | Flask, requests, cryptography. |
| `requirements-flux.txt` | Diffusers / transformers / Hugging Face Hub (used with PyTorch). |

Compose on the operator PC (`docker-compose-node.yml`) is generated by **Setup** on the site. Do not commit API keys or `HF_TOKEN`.

## Build and run (operators)

Use **Setup a node** on LocalLLMBay, paste the compose snippet, then:

```bat
startNode.bat
```

Or from this directory, after you have a key and `API_BASE`:

```bash
docker build -t localllmbay-node:latest .
```

Typical environment (values come from Setup — never publish `API_TOKEN`):

| Variable | Meaning |
|----------|---------|
| `API_BASE` | Orchestrator URL |
| `API_TOKEN` | Node key (`localllmbay_live_…`) |
| `NODE_NAME` | Label on the dashboard |
| `NODE_FAMILY` | e.g. `graph,gemma,flux2` |
| `NODE_MODELS` | Ollama tags to pull; Flux/Wan tags trigger Hugging Face instead |
| `NODE_NUM_CTX` | Graph hops use **16384** |
| `OLLAMA_MODELS` | Weight volume, usually `/app/models` |
| `HF_TOKEN` | Optional; faster Hub downloads (public models work without it) |

Health: container port **5000**. Ollama inside: **11434** (not for agents — agents use `/v1` on the server).

## Graph pack (text)

Default Setup pull (when VRAM/RAM/disk fit):

- `granite3.3:8b` — plan / orchestrator  
- `deepseek-coder:6.7b` — thinking (and related hops)  
- `qwen2.5-coder:7b` — final `tool_calls`  

Leftover disk may add `gemma3:4b` (docs). GPU **6 GB+** may add Flux 4B. Video is a separate family when packed.

Under **2 GB** VRAM is blocked. **2–4 GB** pulls only the DeepSeek 6.7B sketch tag as a GPU+RAM split.

## Security (read this before you contribute)

- Treat `API_TOKEN` like a password.  
- Transport crypto protects the wire; **you** can still see prompts on a machine you operate.  
- Do not turn on plaintext prompt logs against the public API.  
- Do not open issues that paste live keys, job plaintext, or other people’s prompts.

## Starter issues (please file or comment)

Until these exist on the tracker, you can open them from [New issue](https://github.com/PjuralSzymon/OllamaBay/issues/new/choose):

1. **Public node-only publishing** — Confirm what stays private (server, website, secrets) vs this folder.  
2. **Smaller node image** — PyTorch in the Dockerfile is large; optional CPU-only / no-Flux build.  
3. **Document `HF_TOKEN`** — Unauthenticated Hub downloads work but can be slow; optional token in compose (never commit it).  
4. **Ollama vs Diffusers** — Text stays on Ollama; Flux/Wan cannot use Ollama generate. Track docs and error messages.  
5. **GPU sharing** — Unload Ollama before Flux/Wan; report OOMs on 8 GB cards.  
6. **Windows / WSL / Docker Desktop GPU** — What Setup should warn about.  
7. **Your idea** — Anything you want different in `node/`.

We will treat comments on those threads as the product backlog for the worker you install.

## Comments and changes we want from you

This public node repo is the place to talk. Please **[open an issue](https://github.com/PjuralSzymon/OllamaBay/issues/new/choose)** if you:

- Want a smaller Docker image, CPU-only image, or a different CUDA wheel  
- Want AMD/Intel GPU paths that actually generate images  
- Hit OOM, slow loads, or bad fit/speed grades  
- Want another open-weight image/video stack instead of Diffusers  
- Want clearer logs, Windows/WSL notes, or a non-Docker install  
- Disagree with a pull skip (`start.sh` / `adapt.py`)  
- Have a licence or attribution correction for a model card we pull  

Use the issue templates when they fit. Informal notes are fine. We would rather have a noisy tracker than silent operators.
